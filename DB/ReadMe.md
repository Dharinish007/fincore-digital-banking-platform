## 📌 Overview

Milestone 4 introduces an **AI-integrated KYC (Know Your Customer) module** into the FinCore Digital Banking Platform.

The Database module is responsible for storing and managing the results generated by the AI services for:

- 📄 **Document OCR** — Extracts customer information from identity documents.
- 🧑 **Liveness Detection** — Verifies that the captured person is a real/live person.
- 🤳 **Face Match Accuracy** — Compares the customer's face and returns a match result with confidence.

The M4 database is designed to remain **connected with the existing database architecture from previous milestones** through the `customer_id` relationship.

## 📊 M4 Database Tables

### 1️⃣ `document_ocr`

> Stores the information extracted by the AI Document OCR service.

| Field | Data Type | Key / Constraint | Description |
|---|---|---|---|
| `ocr_id` | BIGINT | PK, AUTO_INCREMENT | Unique OCR record ID |
| `customer_id` | BIGINT | FK | Links OCR result to customer |
| `document_type` | ENUM | NOT NULL | Aadhaar, PAN, Passport, Driving License, Voter ID, etc. |
| `document_reference` | VARCHAR(255) | — | Reference/path of uploaded document |
| `extracted_name` | VARCHAR(150) | — | Name extracted by AI |
| `extracted_id_number` | VARCHAR(100) | — | Document ID extracted by AI |
| `extracted_date_of_birth` | DATE | — | Date of birth extracted by AI |
| `extracted_gender` | VARCHAR(20) | — | Gender extracted by AI |
| `extracted_address` | TEXT | — | Address extracted by AI |
| `ocr_confidence` | DECIMAL(5,2) | 0–100 | OCR confidence score |
| `ocr_status` | ENUM | NOT NULL | Pending / Processing / Verified / Failed |
| `processed_at` | TIMESTAMP | — | OCR processing time |
| `created_at` | TIMESTAMP | DEFAULT | Record creation time |

---

### 2️⃣ `liveness_detection`

> Stores the result generated by the AI Liveness Detection service.

| Field | Data Type | Key / Constraint | Description |
|---|---|---|---|
| `liveness_id` | BIGINT | PK, AUTO_INCREMENT | Unique liveness record ID |
| `customer_id` | BIGINT | FK | Links result to customer |
| `capture_reference` | VARCHAR(255) | — | Reference/path of captured media |
| `liveness_score` | DECIMAL(5,2) | 0–100 | AI liveness confidence score |
| `liveness_threshold` | DECIMAL(5,2) | DEFAULT 80.00 | Minimum passing threshold |
| `detection_result` | ENUM | NOT NULL | Pending / Passed / Failed |
| `checked_at` | TIMESTAMP | — | Verification time |
| `created_at` | TIMESTAMP | DEFAULT | Record creation time |

---

### 3️⃣ `face_match`

> Stores the AI Face Match Accuracy result.

**The table is intentionally kept minimal according to the M4 UI requirement.**

| Field | Data Type | Key / Constraint | Description |
|---|---|---|---|
| `face_match_id` | BIGINT | PK, AUTO_INCREMENT | Unique face match ID |
| `customer_id` | BIGINT | FK | Links result to customer |
| `match_result` | ENUM | NOT NULL | SUCCESS / FAILED |
| `confidence` | DECIMAL(5,2) | 0–100 | Face match confidence percentage |
| `created_at` | TIMESTAMP | DEFAULT | Record creation time |
